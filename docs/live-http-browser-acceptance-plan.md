# Live Muse HTTP/browser acceptance — November 3

Authorised by the explicit request to prepare and execute **one fresh isolated live test**. This is browser/HTTP integration acceptance, not another attempt to force a social storyline.

## Envelope

- Normal sixteen-resident Unity Gardens with the existing `7g-d-society` reasoning/mechanics boundary.
- **96 maximum Muse invocations, $2 incremental ceiling**, 8,000 input / 2,048 output tokens and the reviewed 30-second shared preflight/generation deadline.
- Six generations/minute; one pending inference; no retries or resumption.
- Native **1,800 simulated-second bound** and **30 wall minutes**, including a 30-second inference headroom stop. The generation ceiling will normally bind first. The earlier 900-second preparation target is superseded by this native hard bound; no separate clock mechanism is added.
- Full-run worst-case reservation: **96 × $0.018704 = $1.795584** at standard $1.25/million input and $4.25/million output, with no cache discount assumed. Recheck pricing and headroom immediately before execution.
- Existing temporary $50 daily/$100 cumulative allowances and November 5 Lagos reversion unchanged. Available credits are not a target.

## Isolation and evidence

The production build is served by the existing HTTP server on loopback port **8791**, from a fresh uniquely named world/checkpoint. A separate expiring approval and exclusive one-shot claim are required. The operating backend, saves and old evidence are never loaded as the active town or resumed.

The existing Meta provider supplies meaningful choices through the selective provider. Only already accepted delivery execution may use the existing deterministic continuation. Movement, work timers, food, payments and delivery mechanics remain authoritative. Player-triggered inference is excluded from this acceptance budget.

The runner records exact scoped inputs/instructions/schema, raw structured decisions, metrics, validation and execution events, committed frame sequence, SSE observer counts and sanitised provider HTTP path/status/timing. Headers, cookies and keys are not recorded. All artifacts go to a new ignored directory under `output/http-muse-acceptance/`. The temporary access token is stored privately there and never placed in URLs or Git.

## Acceptance sequence

1. Verify model/pricing, key configuration, native token limits, complete reservation headroom, ledger prefix, no unresolved spending transaction, operating snapshot validity, source/build hashes and a new execution window. Offline regressions must pass first.
2. Start paused. Confirm unauthenticated access is denied, the browser signs in through the normal token form, and browser session/world identifiers match the actual live server. Confirm **Live Meta / backend**, not a local/mock fallback.
3. Resume through the browser. Match actual returned model decisions and authoritative event IDs against the activity feed/event inspector. Select and inspect all sixteen residents; inspect phones without acquiring control or sending messages.
4. Pause and refresh. Record the committed time/state and request count. A result arriving after a deliberate operator pause must be accounted for but never executed or retried. Reconnection and refresh must retain the same world and checkpoint state.
5. Resume, navigate away from the app for at least 60 wall seconds, and verify **zero SSE observers**, continued provider reasoning and deterministic progress. Reconnect to the same world and higher committed sequence. The browser's bounded recent event window is not a complete audit archive.
6. Check authentic communication/contact/resource/economic representations where events occur naturally. Do not seed invitations, send player prompts or require a particular resident reply. Check desktop/mobile layout and console.
7. Stop on generation/time/spending bounds, evidence/accounting/privacy failure, serious validation or provider failure. Preserve pending failure evidence. Do not retry a failed request or start a second run automatically. Verify core HTTP safe-stop if a failure occurs naturally; otherwise label failure-path evidence as offline fault injection.
8. Verify final checkpoint, exact usage/cost, reservation delta, historical prefix, all protected hashes and absence of duplicate execution. Archive an honest report, including unobserved cases.

## Recording and public-access boundary

Any browser capture must show the real mode and use only observed events. A final recording draft may use acceptance footage after the behaviour is verified; it must not portray offline fixtures, paused state or prior runs as a current live session. No extra inference is authorised merely to reproduce a scene after the run ends.

The loopback operator service is **not a public deployment**. Prepare public video/repository submission materials separately. Do not expose its token, backend key, privileged endpoints or ignored evidence directory. Deployment, publishing, committing and pushing remain unapproved.
